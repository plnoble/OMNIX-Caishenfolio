## 背景

WP-02 收口了 FX-02 与 FX-04，留下三件事，本包一次做完：

1. **FX-03（统筹的规格漏项）**：WP-02 任务书背景说「FX-02/03/04 一并收口」，但步骤与验收只写了两条。FX-03 指**换汇来源现金不受余额约束**——空账本直接记一笔换汇，重放后留下负现金。开发方如实上报并补了特征化测试钉住当前行为。
2. **提醒身份碰撞（Codex 第 7 条，未修）**：去重键是 `Kind|Symbol|Title`（`AlertGatekeeper.cs:131`），两条阈值不同的同类规则会共享一个键，**一条送达会把另一条压掉**。
3. **「现在换」只给毛额盈亏**：毛额系统性高估到手金额，而用户问的恰恰是「到底赚没赚」。

## 目标（用户能得到什么）

1. 记一笔换汇时，**花出去的钱必须是账上真有的**；没有就当场拒绝并说清差多少，不再静默留负数。
2. 分档换汇的多条规则**各自独立送达**，不会因为先触发一条就把另一条压没。
3. 「现在换」的盈亏按**扣掉成本后的净额**说话；成本未填时如实说「净额未知」，不拿毛额冒充。

## 统筹已查清的下游规则（查到代码行，不要凭印象推翻）

**R1 余额约束的落点在重放，不在界面。**
`PositionCalculator.Replay` 的 `FxExchange` 分支直接 `AddCash(…, -(CashAmount + Fee))`（`PositionCalculator.cs:96-100`），不检查余额。界面拦截挡不住 CSV 导入与既有数据，约束必须在写入/重放这一层。

**R2 既有账本里已经可能有负余额，不能一升级就全报错。**
WP-01/WP-02 的验收夹具本身就是「没有先入金就记换汇」。引入约束会让这些历史数据与既有验收向量同时变成非法。**必须同时改写 A 系列夹具**，并对**既有账本**给出不丢数据的处理方式（见 D2）。

**R3 期初与融资是正当的负数来源，必须留口子。**
`OpeningCash`/`OpeningPosition` 表示「开始记账时就有」，证券融资也确实可以透支。约束只管**新发生的换汇**，不得把这些一并判非法。

**R4 去重键必须带上规则身份，但不能破坏既有去重语义。**
`AlertGatekeeper.KeyOf` 现为 `Kind|Symbol|Title`。扩展时：同一条规则的同一次触发必须仍然只发一次；不同规则必须互不压制。**冷却、重入、UNKNOWN 三态（WP-02 已落地）全部不得回退。**

**R5 已发出的通知状态存在 `alert-state.json`。**
改键会让旧状态失配。必须给出迁移或兼容策略：**旧键不得被当成「从未发过」而导致升级当天重复轰炸**。

**R6 「现在换」的毛/净字段已存在。**
`FxCarryView` 已有 `HeldAdvantageGrossPct` / `HeldAdvantageNetPct` 两个字段（`FxCarryView.xaml.cs:503-506`），路径卡也已区分毛/净。本包是**把结论口径从毛改净**，不是新建计算。净额不可得时显示「未知」，**不得回落到毛额充数**。

**R7 WP-01/WP-02 语义不许回退。** 693 条 C# 与 464 条 Python 必须继续全绿。

## 步骤

1. 先写验收向量（A1–A10），先红后绿。
2. **余额约束**（R1/R2/R3）：重放层拒绝超额换出；期初与融资豁免；错误信息说清「账上有多少、要花多少、差多少」。
3. **夹具改写**（R2）：A 系列先入金再换汇；WP-02 的特征化测试 `TodayAnOverspendExchangeSilentlyLeavesANegativeBalance` 改写为「现在会被拒绝」。
4. **既有账本处理**（D2）：升级不丢数据，历史负余额如实标注而非阻止打开。
5. **提醒身份**（R4/R5）：去重键纳入规则身份；旧状态迁移，升级当天不得重复轰炸。
6. **净额口径**（R6）：结论改用净额；不可得时「未知」。
7. 界面：拒绝提示、历史负余额标注、净额口径文案。

## 验收标准

| # | 场景 | 必须成立 |
| --- | --- | --- |
| A1 | 空账本直接记换汇 100,000 CNY → JPY | **拒绝**，错误说清「有 0、需 100,000、差 100,000」；账本无任何写入 |
| A2 | 先入金 100,000 CNY，再换汇 100,000 | 通过；余额归零不是负数 |
| A3 | 入金 100,000，换汇 100,001 | 拒绝；差额 1 要说出来 |
| A4 | `OpeningCash` 建立期初，再换汇 | 通过（R3 豁免） |
| A5 | 既有账本里已存在负余额 | 升级后**仍能打开**，历史负余额如实标注，不阻止使用（D2） |
| A6 | CSV 导入含超额换汇行 | 该行被拒，错误可见；其余行正常导入 |
| A7 | 两条阈值不同的同类规则同时满足 | **各自送达**，互不压制（R4） |
| A8 | 同一条规则同一次触发 | 仍只发一次；冷却、重入、UNKNOWN 行为不变（R4/R7） |
| A9 | 带旧 `alert-state.json` 升级 | 已发过的不重发；**升级当天不得重复轰炸**（R5） |
| A10 | 「现在换」结论 | 用净额；成本未填时显示「未知」，**不回落毛额**（R6） |
| A11 | WP-01/WP-02 既有测试 | 全绿（R7） |

**测试夹具要求（硬性）：** 至少一条照真实数据形状造的记录（`yyyy-MM-dd`、现有 ID 前缀、六位数人民币/七位数日元量级、含空费用与空备注）。**金额必须合成；不得写入用户真实交易数字，也不得写入本机用户名或含账户名的绝对路径。**
