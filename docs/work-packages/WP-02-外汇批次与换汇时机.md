## 背景

用户的核心诉求是外汇，原话：**「重点是汇率」**。具体两问：

1. 我花 X 人民币买了 Y 日元，目标换成美元——**现在换是赚是亏？**
2. **什么时候换最合适？**

WP-01 已把账本改成账户级现金流，换汇作为跨币种转移记录了**回单双边金额**（`FxExchangeHistory` 已可读出 `FromAmount/ToAmount/Fee/Date`）。本包在此之上建立批次与时机判断。

架构审查（报告在仓库外 `D:\Agent\Worktrees\OMNIX-Caishenfolio\reviews\`）指出三条尚未修复的缺陷，本包一并收口：**FX-02、FX-03、FX-04**。

## 目标（用户能得到什么）

1. 每一笔换汇形成一个**批次**：取得日、付出多少、得到多少、现在剩多少、派生成本。再买一次日元就是第二个批次，不混成均价。
2. 对「持有 JPY、目标 USD」给出**现在换的结果**与**盈亏判断**：相对一个明确的比较基准，赚了多少/亏了多少，基准是什么要写出来。
3. 给出**未来临界汇率**：USD/JPY 到多少，现在换与基准持平；比当前汇率还需变动多少。**单位必须是 USD/JPY，不是现在那个 JPY/CNY。**
4. 行情取不到时，提醒与判断给**「本次无法判断」**，不伪装成条件不成立。

## 统筹已查清的下游规则（查到代码行，不要凭印象推翻）

**R1 现有 `breakeven_held_rate` 的单位是错的，不要沿用这个名字。**
`fx_paths.py:631` 为 `breakeven = th.rate / tb.rate`，即 `USD/JPY ÷ USD/CNY`，量纲是 **JPY/CNY**。用户要的是「未来 USD/JPY 的临界值」，是另一个数。新增字段另起名，旧字段保留原语义或明确废弃，**不要就地改语义**——界面和测试都在用它。

**R2 批次数据必须从既有换汇流水派生，不新开一套事实。**
`FxExchangeHistory` 已从流水提取回单（冲正对已排除、方向敏感）。批次是**投影**，不是可独立编辑的新账本。冲正一笔换汇，对应批次必须跟着消失。

**R3 部分换出需要分配规则，默认 FIFO，且必须显式可见。**
不要引入审查报告里那套分配策略/血缘/政策版本的完整模型——**超出当前需要**。本包只要：按取得日先进先出消耗，界面能看出这次消耗了哪些批次、各消耗多少。

**R4 第三币种换入不能继承原始成本。**
CNY→JPY→USD：USD 批次的成本是**本段**付出的 JPY，不是最初的 CNY。最初投入属于另一条链路的表现基准，要分开展示，不能重复计入已确认的利润。

**R5 FX-02：金额已知、历史成本未知时，不许把整个持仓置空。**
`AnalyticsCoreClient.PostFxPathsAsync` 现在在成本缺失时把 held 整体置为空，Python API 也要求 `amount` 与 `cost_in_base` 同时有值（`server/app.py`）。结果是：明明知道有 2,105,347 JPY（示例数量级，非真实），能算市场估值和假设到账，却只剩 `base_to_target` 一条路径。**正确行为：数量已知就能估值、能比较路径，只有「收益」不可得。**

**R6 FX-04：提醒必须有 TRUE / FALSE / UNKNOWN 三态。**
`FxRuleEvaluationResult` 有 `Notes` 但 `BackgroundExtendedCheck.RunAsync` 只传 Alerts，Notes 丢失；`AlertGatekeeper.Filter` 把本轮没出现的事件一律记成「离开区间」。报价失败≠条件变假，否则恢复后会伪造一次「重新进入」。UNKNOWN 必须保留上次有效判断并记录失败原因，**不推进冷却、不触发新入场**。

**R7 未知成本不得变成零。**
`PathCost` 的三态语义（未填=未知 / 0=确认无）已在单段与绕行两条路径上统一（基准内 `20ae434` 修过绕行分支把未知固定费当零的缺陷）。新增任何路径或腿都必须守同一条线。

**R8 WP-01 的既有语义不许回退。**
账户估值模式、「当天资产金额」不是现金流、转移在组合层不计外部流、多币种按发生日折算、缺率标不完整——这些都有测试钉死，必须继续全绿。

## 步骤

## 验收标准

| # | 场景 | 必须成立 |
| --- | --- | --- |
| A1 | 两次换汇买入 JPY（不同汇率） | 形成**两个批次**，各自取得日/付出/得到独立；不合并成均价 |
| A2 | 换出一部分 JPY | 按取得日 FIFO 消耗；消耗明细可见（哪批、各多少）；剩余量守恒 |
| A3 | 冲正其中一笔换汇 | 对应批次消失，剩余量回到冲正前（R2） |
| A4 | CNY→JPY→USD 全链 | USD 批次成本是**本段付出的 JPY**，不是最初 CNY（R4）；最初投入可另行展示但不混入 |
| A5 | 持有 JPY、目标 USD，报价齐全 | 给出到账 USD、盈亏、**基准名称与冻结时点**随结果返回 |
| A6 | 同 A5，求未来临界 USD/JPY | 单位为 **USD/JPY**；与旧 `breakeven_held_rate` 是不同字段、不同数值（R1） |
| A7 | 同 A6，再给「相对当前还需变动百分比」 | 例：当前 160、临界 150 ⇒ 还需下降 6.25%（`(r−T)/r`） |
| A8 | 数量已知、历史成本未知 | 仍返回估值与全部可算路径；**只有「收益」为不可得**（R5） |
| A9 | 某条路径部分费用未填 | 该路径 `gross_only`、净额 None；不得出现 `0.0` 充当未知（R7） |
| A10 | 提醒求值时报价取不到 | 状态为 **UNKNOWN**；保留上次有效判断；**不推进冷却**；失败原因可见（R6） |
| A11 | UNKNOWN 之后报价恢复且条件仍成立 | **不得**产生一次伪造的「重新进入」提醒 |
| A12 | WP-01 全部既有测试 | 全绿，语义未回退（R8） |
