## 目录约定

worktree、审核目录、临时数据一律放 `D:\Agent\Worktrees\OMNIX-Caishenfolio\`，不散在项目目录里。

含真实用户数据的审查报告放 `D:\Agent\Worktrees\OMNIX-Caishenfolio\reviews\`，**不进仓库**——本仓库是公开的。

## 开发 agent 的交付要求

1. 从任务书写明的基准提交开新分支，在自己的 worktree 里做。
2. **不在 main 工作区留未提交改动。** 开发记录写在自己分支，随合并进入 main。
3. 交付前在**全新 worktree** 里对**已提交**的提交跑全套检查，Debug 与 Release 均零警告。
4. 自己调 Codex 审一遍，附报告路径与结论。
5. 交付 MD 写：改动文件、通过/失败/未运行各是什么、命令与证据、遗留边界。**失败也保留**，不许重试筛绿灯。

## 统筹的验收规矩

1. **不信交付报告。** 在全新 worktree 里对交付提交自己跑一遍全套检查。
2. 批准修复前，用**原始失败记录里真正失败的那条**复现，不信转述、不信相近样例。
3. 核实"不会出事"之后再问一句：**它本来应该是什么样？**
4. 界面验收：给测试版开调试端口用脚本点，不截用户桌面、不往桌面窗口发按键；宽窄窗口各看一次；用户自己的安装版开着时不启动测试程序。
5. 截图与日志逐份检查，不得含个人内容、本机用户名、真实金额。**公开仓库里不放截图。**
6. 审核报告写进仓库：结论、验证了什么、必须改的（每条附"什么输入会出什么错"）、统筹自己改了什么。

## 统筹自己改的门槛

小到「写清问题 + 等 agent 改 + 再复审」比「自己改 + 跑一次检查」更费时，就自己改：一两处文案/默认值/边界、清警告、补一两条测试、修文档、解冲突。大致 ≤20 行且无设计取舍。

自己改之前确认 agent 没在同一分支干活；只提交自己改的文件；跑全套检查；在给 agent 的交接里写明「统筹已改：哪个提交、改了什么」。
