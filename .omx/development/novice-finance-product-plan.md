> 文档用途：供后续开发 Agent、审查 Agent 和产品验收直接读取。
>
> 制定日期：2026-09-04  
> 当前产品版本：以仓库根目录 `VERSION` / `PHASE` 为唯一准确信息。  
> 产品边界：个人多市场、多资产财富工作台；不连接券商下单，不自动执行换汇，不承诺收益。

## 1. 开工前必读

任何 Agent 开始修改前，必须完整阅读：

1. 根目录 `AGENTS.md`；
2. `.claude/skills/agent-dev-protocol/SKILL.md`；
3. `.omx/development/current.md`；
4. `.omx/development/handoff.md`；
5. 本文件。

必须遵守的底线：

- C# Host 继续拥有路径、权限、凭据、进程和审计权威；Python Core 只负责受控分析。
- 金额必须使用 `Money` 或 `decimal + currency`，禁止用 `double` 做资金计算。
- 数据源失败时 fail-closed，禁止用 fixture、旧缓存或猜测值伪装实时数据。
- 未定价资产不得按 0 计入总资产；估值不完整时必须明确显示“未知/不完整”。
- 所有研究、模拟和证据卡必须带非投资建议声明、数据时间和来源。
- 禁止接入实盘下单、自动换汇或在仓库保存长期券商/交易所凭据。
- 不得覆盖用户或其他 Agent 的改动；先检查 `git status` 和相关 diff。
- XAML 或资源字典变更后，除构建和单测外，必须执行 `scripts\ui_smoke.ps1`。

## 2. 产品结论

当前软件适合“愿意学习的个人用户记录资产、做研究和复盘”，但还不适合让完全不懂金融的小白直接依据界面做金融操作。

主要优点：

- 本地优先，没有实盘下单能力，天然降低误操作风险；
- 账本、估值、收益、配置、行情、网格、回测和报告基础较完整；
- 多源行情交叉核验、来源追踪、未定价标识和 fail-closed 方向正确；
- 已有计划价位、集中度、数据陈旧、价格分歧、IPO 截止日等提醒基础；
- 资产类别、地区、币种、现金、单一持仓和最大回撤已有风险分析基础。

主要缺口：

- 页面以功能模块组织，不以“小白今天要完成什么任务”组织；
- 菜单多、术语多、输入项密集，并直接暴露 `SSE:600000` 等内部代码；
- 能展示指标，但缺少“这意味着什么、证据是否充分、哪里可能错”的决策闭环；
- 汇率页面只有当前利差和区间位置，无法读取用户真实换汇成本并比较多条兑换路径；
- 领域层支持 `FxExchange`，手工记账界面却不能录入换汇；
- 后台提醒实际只可靠覆盖 IPO 截止日，设置文案却容易让用户以为价格和集中度也会后台推送；
- 流水被描述为追加式账本，但界面存在物理删除，审计与可追溯性不足；
- 估值不完整时仍可能给出看似确定的集中度结论；
- “AI 建议网格参数”等文案容易让小白高估启发式模型的能力。

建议把产品定位统一为：

> OMNIX 帮用户记录、比较、解释、预警和复盘；提供证据，不替用户预测未来或执行交易。

## 5. N0：账本完整性与数据可信护栏

### 目标

先消除会让小白误信结果、误删历史或误解提醒范围的问题。

### 工作项

#### N0.1 流水更正代替物理删除

- 普通用户界面不再直接物理删除已入账流水；
- 增加“冲正/更正”流程：原流水保留，新建关联的反向或更正记录；
- 保存原流水 ID、冲正流水 ID、操作时间、原因和审计记录；
- 如需保留管理员物理删除，只能用于未提交草稿或开发数据，并与正式账本明确隔离；
- 设计数据库迁移、升级兼容和回滚前备份；
- 不放宽超卖校验，不用删除绕过账本约束。

重点搜索：`LedgerTransaction`、`PortfolioStore`、`LedgerView`、DELETE 语句、流水删除命令。

#### N0.2 估值不完整时禁止输出“正常”

- 任意未定价持仓或关键汇率缺失时，组合总值状态必须为“不完整”；
- 集中度只能标成“基于已定价部分”，不得显示全组合绿色正常结论；
- 关键分母不可靠时，风险规则返回 `Unknown/InsufficientData`，而不是 `Pass`；
- UI 同时显示未定价资产数量、列表、缺失原因和最近一次成功时间。

重点搜索：`PortfolioRiskAnalyzer`、估值汇总、集中度卡片、未定价提示。

#### N0.3 修正提醒能力文案

- 当前后台进程如只检查 IPO 截止日，设置页必须明确写出；
- 在 N3 扩展完成前，不得声称关闭主程序后仍会推送价格与集中度提醒；
- 设置页增加“最近检查时间、检查范围、上次结果”。

重点搜索：`HeadlessNotifier`、`IncludeRoutineAlerts`、设置页提醒文案。

#### N0.4 文档与版本口径一致

- 版本和阶段只从根目录 `VERSION` / `PHASE` 读取；
- 修正 README、AGENTS、current、handoff 中过时版本描述；
- 禁止在业务代码中新增版本字面量。

### 验收标准

- 已入账流水不能在普通流程中无痕消失；
- 冲正前后现金、持仓、成本和收益可验证，审计链完整；
- 含一个未定价大额持仓时，界面绝不显示“组合风险正常”；
- 关闭主程序后的提醒能力与设置文案完全一致；
- 迁移、备份恢复、旧数据库打开均有测试；
- 相关 C# 单测、Python 单测和契约测试通过。

## 6. N1：小白模式与任务型首页

### 目标

让第一次打开软件的人不需要理解全部金融术语，也能完成建账、查看风险和设置提醒。

### 产品结构

新增两种呈现模式：

- 小白模式：默认启用，以任务和解释为主；
- 专业模式：保留现有研究页面和高级参数，不删除老用户能力。

小白首页建议只回答四个问题：

1. 我现在有多少钱，哪些数字还不确定？
2. 我的钱主要暴露在哪些资产、地区和币种？
3. 今天有什么需要处理？
4. 如果进行某项操作，我的组合会发生什么变化？

### 工作项

- 首次引导采集：本位币、目标、资金期限、应急金、流动性需求、可承受最大回撤、关注市场；
- 首页卡片：资产状态、待处理事项、数据异常、风险变化、提醒状态；
- 证券搜索支持名称、拼音、简称和代码，内部代码只作为次要信息；
- XIRR、TWR、回撤、分位数、carry、复权、滑点等术语提供就地白话解释；
- 高级参数折叠，常用任务做成向导；
- “真实账本”“研究模拟”“历史回测”使用稳定、明显的视觉区分；
- 将“AI 建议”改为“规则估算/历史参数建议”，除非确实有可审计 AI Task 和证据链；
- 新视图使用独立 View/ViewModel/Service，不继续把逻辑堆入 `MainWindow.xaml.cs`。

### 验收标准

邀请从未用过本软件的测试者，在没有口头指导的情况下完成：

1. 创建账户；
2. 录入一笔现金；
3. 录入一笔持仓；
4. 找到未定价提示；
5. 看懂最大风险来源；
6. 设置一个提醒；
7. 解释真实账本与回测结果的区别。

以上关键任务不得要求用户手输 `SSE:`、`NASDAQ:` 等内部前缀。

## 7. N2：换汇记账与兑换路径决策实验室

### 目标

准确回答“我已有日元，换美元更划算，还是新拿人民币换美元更划算”，并把费用、汇差、数据时效和不确定性说清楚。

### N2.1 手工换汇记账

领域层已经支持 `TransactionKind.FxExchange`，但手工账本界面尚未暴露。新增换汇向导：

- 换出账户和币种；
- 实际换出金额；
- 换入账户和币种；
- 实际到账金额；
- 手续费金额及币种；
- 成交时间、机构、备注和可选回单引用；
- 展示根据两边实际金额计算出的成交汇率，但不反过来用汇率推算到账金额。

必须保持规则：换汇按回单两边金额入账，避免 decimal 反推残差。

### N2.2 多路径比较

至少支持同时比较：

- 已持有 JPY → USD；
- 新资金 CNY → USD；
- CNY → JPY → USD；
- 暂不兑换；
- 分批兑换。

每条路径输出：

- 起始资产与机会成本；
- 毛到账金额；
- 点差、固定手续费、比例手续费和估计滑点；
- 净到账金额；
- 与其他路径的绝对差和百分比差；
- 盈亏平衡汇率；
- 数据来源、数据时间、报价方向、是否为可成交报价；
- “数据不足”或“成本输入缺失”状态。

统一汇率显示方向：

> `FROM → TO：1 单位 FROM 可兑换多少单位 TO`

所有内部交叉汇率必须显示公式和原始行情来源，避免方向混淆。

### N2.3 相对优势分析，不预测绝对最高点

如果用户过去以 `E` JPY/CNY 的实际成交价把 100 CNY 换成日元，当前行情为：

- `USD/CNY = C`，含义为 1 USD = C CNY；
- `USD/JPY = J`，含义为 1 USD = J JPY；
- 当前隐含 `CNY/JPY = J / C`。

忽略费用时：

```text
旧日元路径可得 USD = 100 × E / J
新人民币直换可得 USD = 100 / C
旧路径相对优势 = E / (J / C) - 1
```

因此：

- 当历史实际 `CNY/JPY` 成交价高于当前隐含 `CNY/JPY` 时，已有日元路径在毛金额上更有利；
- 优势通常在日元兑美元变强（`USD/JPY` 下降）和/或人民币兑美元变弱（`USD/CNY` 上升）时扩大；
- 真实结论必须扣除各路径点差和费用；
- 软件只能计算“相对当前和历史成本的优势”，不能预知未来利润最大时点。

### 固定验收样例

使用以下仅用于测试公式的参考数据：

- `USD/CNY = 6.7260`；
- `USD/JPY = 159.97`；
- 隐含 `CNY/JPY = 159.97 / 6.7260 = 23.783824...`；
- 100 CNY 直接换 USD，毛额约为 `14.867678 USD`；
- 假设历史以 `24.5 JPY/CNY` 换入 2450 JPY，则换 USD 毛额约为 `15.315372 USD`；
- 旧日元路径在未计费用前约高 `3.011%`。

验收要求：

- 使用 decimal 计算并明确舍入规则；
- 交换报价方向后，结果仍保持数学一致；
- 加入费用后可以出现优势反转；
- 缺少任一关键报价时 fail-closed；
- 参考数据标明为 2026-08-28 前后的官方参考汇率，不伪装成银行实时可成交报价；
- 数据参考：<https://www.federalreserve.gov/releases/h10/current/>。

### N2.4 换汇提醒

支持用户自定义：

- 净到账金额达到目标；
- 旧币路径相对新资金路径优势达到阈值；
- 达到盈亏平衡；
- 汇率进入用户指定区间；
- 报价过期或不同来源分歧过大。

禁止使用“最佳换汇时机已到”作为通知文案。

### 验收标准

用户录入一笔 CNY → JPY 的真实回单后，可以用当前报价比较 JPY → USD 与新 CNY → USD；每一个结果都能追溯到输入金额、费用和来源。

## 8. N3：可信后台提醒

### 目标

让用户准确知道哪些提醒会在主程序关闭后运行，失败时不静默，也不重复轰炸。

### 架构建议

分成两层：

1. 始终本地可用的截止日/日历提醒；
2. 可选的联网价格、仓位、换汇和数据质量检查。

第二层失败不得阻塞第一层。

### 工作项

- 将规则计算抽成无 UI、可单测的纯检查器；
- 前台与后台复用同一套规则和阈值；
- 支持去重、冷却时间、重新进入区间、市场时区和节假日语义；
- 记录最近运行、下一次运行、检查范围、数据时间、发送结果和失败原因；
- 提醒消息不得包含账户凭据、完整本地路径或敏感备注；
- 凭据只通过 Host 安全注入，使用系统安全存储，禁止写入仓库配置；
- 行情过期、数据源冲突或估值不完整时，发“数据异常”而不是操作暗示；
- 为网络失败、超时、限流、系统休眠、重复唤醒和时区边界增加测试。

### 验收标准

- 设置页声明的后台提醒类型都能在关闭主窗口后被实际验证；
- 同一事件不会在冷却期内重复通知；
- 扩展检查失败时，IPO/截止日提醒仍继续；
- 用户能在界面看到上次检查为何失败；
- 提醒只描述触发事实，不替用户下买卖结论。

## 9. N4：股票决策证据卡

### 目标

不直接告诉小白“买/卖”，而是帮助其判断：证据是否充分、承担了什么风险、什么条件会推翻原判断。

### 输入

- 标的；
- 候选投入金额；
- 持有期限；
- 可承受最大损失；
- 比较基准；
- 可选的用户投资理由。

### 输出结构

1. 数据质量：来源、时间、缺失、冲突、复权方式；
2. 当前估值：只展示可验证指标，并说明口径；
3. 基本面：收入、利润、现金流、负债等趋势；
4. 市场行为：趋势、波动、回撤、成交活跃度；
5. 历史检验：样本内/样本外、交易成本、参数敏感性；
6. 组合影响：买入后单一持仓、行业、地区、币种和现金比例；
7. 正面证据、反面证据、未知项；
8. 失效条件：什么事实出现后应重新评估；
9. 结论状态：证据偏正面、证据冲突、风险超限或证据不足。

### 质量门

- 新鲜度检查；
- 来源白名单与来源链接；
- 数值可追溯到原始数据和公式；
- 多源冲突检测；
- 缺失数据不得由大模型补写；
- 文字结论必须与数值方向一致；
- 卖出分析必须列出税费、机会成本和组合影响；
- 所有研究输出映射到 Task / Artifact / Audit；
- 回测采用滚动样本外、费用敏感性和参数扰动，明确过拟合风险。

### 禁止项

- 不输出“必涨”“稳赚”“最佳买点”；
- 不自动生成或执行订单；
- 不把历史回测收益当未来预期；
- 不用单一技术指标、社交热度或 LLM 文本作为操作依据。

### 验收标准

- 数据不足时可以明确停止并输出“证据不足”；
- 输入候选金额后，用户能看到交易前后组合风险对比；
- 每一条关键结论都能定位到来源、时间、公式或规则；
- 任一来源失败不会被伪造数据掩盖。

## 10. N5：仓位、收益归因与压力分析

### 目标

从“显示比例”升级为“解释风险来自哪里，以及一次操作会让风险怎样变化”。

### 第一批能力

- 持仓对盈亏和回撤的贡献；
- 汇率变动与资产本身涨跌的收益拆分；
- 单一持仓、资产类别、地区、币种、现金的集中度；
- 目标配置偏离；
- 用新增资金再平衡与卖出再平衡的比较；
- 应急金单独标记，不把它误判为“现金闲置”；
- 操作前后仓位模拟，不写入真实账本。

### 压力场景

至少支持用户可理解、可编辑的情景：

- 股票市场下跌；
- 日元、美元、人民币相对变化；
- 利率上升或下降；
- 单一最大持仓下跌；
- 多个风险因子同时变化。

场景结果必须标为假设分析，不应称为预测。

### 后续能力

只有在数据质量足够时再加入：

- 行业集中度；
- 相关性和共同回撤；
- ETF 重叠持仓；
- 债券久期、信用和流动性风险。

数据不足时输出未知，禁止根据名称猜行业或底层持仓。

### 验收标准

- 能解释组合一次较大回撤由哪些资产和汇率造成；
- 候选买入会导致单一持仓或币种超限时，在提交前明显警告；
- 应急金不会触发普通闲置现金提醒；
- 所有压力结果能复算并明确输入假设。

## 11. N6：场景化金融教育

### 目标

建立原创的“小白 → 进阶 → 高阶”学习路径，但内容出现于任务发生的位置。

### 内容结构

- 小白：账户、现金、持仓、成本、收益、汇率方向、手续费、分散；
- 进阶：XIRR/TWR、回撤、再平衡、相关性、汇率归因、回测偏差；
- 高阶：样本外验证、参数敏感性、因子暴露、流动性、债券久期和信用。

### 呈现方式

- 首次出现术语时的一句话解释；
- “为什么会提示我”展开卡；
- 带软件内真实字段的可复算小例子；
- 风险提示旁提供下一步学习入口；
- 不用长篇 PDF 阻断主要任务。

### 版权要求

- 所有内容原创或引用明确允许使用的来源；
- 不复制 `Financial_freedom` 中的 PDF；
- 引用外部材料时记录来源、许可和访问日期。

## 12. N7：测试、可访问性与发布加固

### 必测范围

- C# 全量单测；
- Python 全量单测；
- C#/Python API 契约；
- SQLite 迁移、备份与恢复；
- 行情源失败、超时、过期、冲突和限流；
- FX 报价方向、交叉汇率、费用、舍入和盈亏平衡；
- 后台提醒去重、时区、休眠唤醒和失败隔离；
- 账本冲正、成本、收益、超卖和未定价语义；
- 键盘操作、焦点顺序、高对比度、缩放和屏幕阅读器标签；
- 安装、升级、自动更新和旧数据库兼容；
- 所有 XAML 变更执行真实启动 smoke。

### 小白端到端验收脚本

1. 首次启动并选择人民币为本位币；
2. 创建现金账户并录入 100 CNY；
3. 录入一次 CNY → JPY 的真实换汇；
4. 比较已有 JPY → USD 与新 CNY → USD；
5. 加入手续费后观察路径结论是否可能反转；
6. 创建净到账或相对优势提醒；
7. 搜索一只股票并生成证据卡；
8. 模拟买入后查看仓位变化；
9. 查看压力情景和最大风险来源；
10. 冲正一笔错误流水；
11. 断网或制造缺价，确认软件明确显示未知且不输出绿色正常结论。

## 13. Agent 分工建议

为降低冲突，每个 Agent 只领取一个明确阶段或文件集合。推荐如下：

| Agent | 责任 | 主要所有权 |
|---|---|---|
| A | N0 账本完整性 | `PortfolioStore`、流水模型、迁移、账本测试 |
| B | N2 FX 分析 | Python FX 研究、服务端 API、`AnalyticsCoreClient`、契约测试 |
| C | N1 小白 UI | 新首页、新向导、导航和 ViewModel；唯一允许集中修改 `MainWindow` 的 Agent |
| D | N3 提醒 | `HeadlessNotifier`、提醒规则、调度、提醒设置区 |
| E | N4 股票证据卡 | Python research 模块、报告契约、质量门和测试 |
| F | N5 组合分析 | `PortfolioRiskAnalyzer`、归因、压力分析、组合 UI |
| G | N6/N7 教育与 QA | 原创文案、端到端验收、可访问性、smoke、发布文档 |

### 冲突规则

- `MainWindow.xaml` / `MainWindow.xaml.cs` 默认只由 Agent C 修改；其他 Agent 通过新 View、ViewModel、Service 和最小接线提交需求；
- `PortfolioStore` 在 Agent A 合并前不由其他 Agent 修改；
- Python 服务入口和 `AnalyticsCoreClient` 优先只由 Agent B 修改，其他分析 Agent新增独立模块并提供接线说明；
- 提醒设置 UI 由 Agent D 在 Agent C 完成导航/布局后接入；
- 数据库迁移编号由 Agent A 统一分配；
- 若无法避免同文件改动，后开始的 Agent 必须先读取最新 diff 并在 handoff 中说明兼容方式。

## 15. 审查顺序

### Gate A：N0

重点审查账本不可抵赖性、迁移安全、未定价语义、提醒文案真实性。未通过不得继续宣传为小白可用。

### Gate B：N1～N3

重点审查首次使用任务、FX 公式与方向、费用反转、后台提醒真实性、XAML 运行时加载。

### Gate C：N4～N5

重点审查数据追踪、样本外验证、过拟合、组合前后对比、未知状态和研究免责声明。

### Gate D：N6～N7

重点审查原创内容、无障碍、端到端测试、升级兼容、版本一致性和发布材料。

审查发现问题时，按严重度优先报告：

- P0：可能造成账本损坏、错误金额、泄密、越权或把未知显示成确定；
- P1：可能误导用户执行金融操作，或核心流程不可用；
- P2：一般功能、兼容、性能或可用性问题；
- P3：文案、结构和低风险体验问题。

## 16. 全局 Definition of Done

只有同时满足以下条件，才可以宣称“适合小白进行辅助分析”：

- 用户可以完整记录现金、持仓和换汇，错误通过冲正修复；
- 任何关键数据缺失都明确显示未知，不伪造、不静默降级；
- 汇率比较包含历史实际成本、全部费用、报价方向、时效和来源；
- 股票页面提供证据与风险，不输出确定性买卖指令；
- 操作前能显示仓位和风险的变化；
- 后台提醒能力与界面承诺一致，并能看到失败原因；
- 小白不需要输入内部证券代码即可完成关键任务；
- 真实账本、研究模拟和历史回测始终清楚区分；
- 全量测试、迁移测试、UI smoke 和端到端小白验收通过；
- 产品继续保持“无实盘下单、无自动换汇、无收益承诺”的边界。

## 17. 风险声明

本计划设计的是金融信息整理和决策支持软件，不是投资顾问、交易系统或收益预测器。市场择时本身困难，频繁交易还会增加费用与错过市场的风险；产品应鼓励用户结合资金期限、风险承受能力和分散配置做判断，而不是把任何单一模型包装成答案。
