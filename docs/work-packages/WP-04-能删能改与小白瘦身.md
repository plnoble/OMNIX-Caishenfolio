## 背景

用户用了一轮 v0.14.0 之后给了三条反馈，原话：

1. 「你觉得小白模式就是给一大堆的字去解释，但是小白反而是没心情看也看不懂这么多字的。小白反而需要的是简洁的画面，最简单的操作。」
2. 「账本不能删就已经是垃圾了。」
3. 「怎么把计划买计划卖的线清了。」

三条都已被统筹接受，判断如下，**不要重新论证，照做**：

- 第 2 条是统筹在 WP-01 N0.1 定的规矩错了。「只能冲正不能删」那套是给多人、要审计、要对外出报表的系统定的。这里是一个人记自己的账，绝大多数要删的行就是几秒钟前打错的数，强迫用户为一个笔误再记一条反向流水是把专业洁癖套在用户身上。
- 第 1 条是统筹把「小白」理解成「需要被解释的人」，于是往屏幕上堆字。小白是**没耐心看字的人**。方向是**少**，不是多。
- 第 3 条的根因已查清：`ChartDrawMode.PickPlanBuy/PickPlanSell` 在 `OnChartPricePicked`（`MainWindow.xaml.cs:1039`）之后**不复位**。`MainWindow.xaml.cs` 里 `_chart.Mode = ChartDrawMode.*` 只出现在六个手动按钮处（968 / 979 / 990 / 1001 / 1018 / 1035），没有任何一处在成功点选后回到 `Crosshair`。于是进了点选模式以后，在价格区每点一下就静默写一条计划线。用户不是想加多条，是在图上点了多下。

## 目标（用户能得到什么）

1. 账本页能**删**、能**改**，删错了能从**回收站**找回来。不再被迫用冲正改笔误。
2. 小白首页第一屏只有「我有多少钱」和「记一笔 / 换汇」两个动作，别的都收起来（**不是删掉**）。
3. 图上点选计划线点一次就结束；计划页能一次删多条，也能一键清空当前标的。
4. 小白点「换汇」一屏填完就记完，不必先翻到账本页、再在类型下拉里找「换汇」。
   用户原话「重点是汇率」——换汇是他最想要的那条路径，当前它被埋在最深处。

## 步骤

### 阶段 1：账本软删除内核（schema v11）

1. `transactions` 加三列：`voided_at TEXT NOT NULL DEFAULT ''`、`void_reason TEXT NOT NULL DEFAULT ''`、`supersedes_transaction_id TEXT NOT NULL DEFAULT ''`（最后一个给「编辑」用）。建索引。
2. `LedgerTransaction` 加 `VoidedAt` / `VoidReason` / `SupersedesTransactionId` 与 `IsVoided`。
3. `PortfolioStore` 加 `VoidTransaction(id, reason)`、`RestoreTransaction(id)`、`ListVoided()`。**不加物理删除。**
4. **F4 的五处全部跳过已作废行**，每处配一条测试。
5. 连带规则（见预先裁定 4）：转账两腿一起作废；作废被冲正的原行时连带作废它的冲正行。
6. 迁移 v10 → v11：已有行全部 `voided_at = ''`，**升级前后 `Replay` 结果必须逐字相同**。

### 阶段 2：账本页 UI

7. 「删除选中」成为主按钮，「冲正选中」降为次级（右键菜单或折叠）。删除要有确认框，框里说清「可以从回收站找回」。
8. 「编辑选中」：对话框预填原值，保存时作废旧行 + 写入新行（`SupersedesTransactionId` 指向旧行）。**不原地 UPDATE。**
9. 「回收站」：列出已作废行，可「恢复」。无自动清理、无过期、无永久删除按钮。
10. 已作废行在主流水表里默认不显示。

### 阶段 3：小白首页瘦身与动作入口

11. 第一屏（1280×800 不滚动）只留：**总资产**一个大数字、**累计收益**一行、**记一笔** 和 **换汇** 两个大按钮、紧急待办（**只在有待办时占位置**，没有就完全不出现）。

12. 其余全部进一个默认收起的「看详细」折叠区：现金、XIRR、最大回撤、你的档案、我的钱在哪里、想做点什么会怎样、学习路径。**一个都不许删。**
13. 展开状态持久化到 `ui.novice.detailsExpanded`。
14. 平铺的名词解释文字从页面上撤下来，改成 tooltip 或「?」。`TermGlossary` 内容不动。

### 阶段 4：点选与计划线

15. `OnChartPricePicked` 成功写入后 `_chart.Mode = ChartDrawMode.Crosshair`；两处提示文案里的「可连续点多个」「可继续点选；十字结束」改成点一次即结束的说法。

## 预先裁定（不要为这些停下来问）

1. **软删除，不是物理删除。** 回收站只能「恢复」，不加「永久删除」。物理清理以后再说。
2. **冲正保留**，语义不同不能合并：作废 = 这条记录根本不该存在（打错了）；冲正 = 这笔交易真发生过但后来被撤销。默认操作是删除，冲正降为次级。
3. **编辑 = 作废旧行 + 新增一行**，不原地 UPDATE。原地改会让已导出的报表对不上，出了问题也查不回去。用户看到的只是一个预填好的对话框。
4. **连带作废**：转账两腿必须一起作废；作废被冲正的原行时连带作废它的冲正行。不是拒绝，是连带。
5. **作废导致后续出现负余额时：警告并允许，不拒绝。** 拒绝会让用户卡死——打错的入金删不掉。受影响的后续行要在账本页标出来。
6. CSV 不导出已作废行；导入去重的键**必须排除**已作废行（A6 的第二半就是在钉这个陷阱）。
7. 迁移 v10 → v11 **不得改变任何已有数字**；复用 F7 的 `.bak` 机制。
8. 小白首页**只折叠，不删功能**。
9. 缺昨日快照就不显示今日变化。**不显示 0，不编数。**
10. 点选默认点一次就退出。**不做撤销**（范围收敛）。
11. 回收站**不做**自动清理 / 过期 / 定时任务。
12. 不改 `VERSION` / `PHASE`，不发版，不推送。
13. 换汇一屏**复用 `RecordWindow` 的换汇分支落库**，不新建第二条记账路径。只加「以指定操作打开」和换汇模式下的字段可见性。
14. 换汇模式下不相关字段**不出现**，不是禁用或置灰。小白看见一个灰着的框只会多一个疑问。
15. 成交汇率**只显示不参与计算**。两边金额永远只来自用户按回单填的数，不许用汇率反推——这是 N2.1 定下来的，不要「顺手优化」。
16. 专业模式下账本页的「记一笔」八字段表单与类型下拉**一个字段都不动**。老用户的路径不许因为小白的需求变形。
17. 小白首页那两个按钮是**新增**，不是把旧按钮改标签。「刷新」和「切换到专业模式」保持可用。

六个阶段各自独立提交。每个提交前至少跑 `dotnet build -c Debug` 和 `dotnet test`。

## 卡住时的处理顺序

1. 先看是不是 F1–F11 里已经写明的事实，别重新推。
2. 预先裁定覆盖到的，照裁定做。
3. 验收向量和实现冲突时，**向量优先**，在交付 MD 里写明哪条向量迫使你改了设计。
4. 真的是任务书没覆盖的设计取舍：按最小改动做一个版本，钉一条特征化测试记录当前行为，在交付 MD 的「遗留边界」里写清，**不要停下来等**。
5. 任何一条验收向量过不去：**保留失败证据**，照实写进交付 MD，不要改向量、不要重试到绿。
