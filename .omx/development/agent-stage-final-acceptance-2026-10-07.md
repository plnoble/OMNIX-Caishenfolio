### A1. 汇率区间与请求归属

使用可控的内存 HTTP handler/TaskCompletionSource，测试数据只作响应标记，不访问真实行情。至少覆盖：

| 场景 | 通过标准 |
| --- | --- |
| 1→5→10→1 顺序成功 | 请求长度、结果行、有效区间标题、tooltip/展开说明无冲突 |
| 1 年成功后 5 年失败 | 保留 1 年结果并明确上次成功区间，不能伪称 5 年已成功 |
| 首次请求失败 | 尚无成功结果，不能宣称已有 1 年数据 |
| 5 年请求慢、10 年请求快 | 两次请求可在逻辑测试中受控并发；旧成功不覆盖新结果 |
| 新成功之后旧失败 | 旧错误不覆盖新状态/结果 |
| 新请求尚未完成，旧请求结束 | 旧 finally 不解除当前请求 busy 状态 |
| 当前请求结束 | 刷新与区间选择可恢复；不得永久禁用 |
| 初始/核心未就绪/各区间 | 年化列始终是当前利率的年化量纲；说明不固定为过去一年 |

页面已禁止加载时操作区间下拉，这一 UI 策略可以保留；对请求序号的测试从可控逻辑入口验证防护，不要求测试靠 UI 强行点击禁用控件。

**旧探针陷阱：**`.local/recheck-7/Probe/Program.cs` 中曾等待“旧 5 年响应覆盖成功”来取证；正确修复后这个等待可能超时。正式回归应等待旧任务确实结束，然后断言结果仍为 10 年；不使用任意 sleep 推测请求已结束。
