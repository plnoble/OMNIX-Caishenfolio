## 8. 关键口径（D8 与 R1/R4 的落地说明）

- **盈亏唯一真相在 Python**（`fx_paths.compare_paths`）。C# 侧的 `FxCarryView` 只把 DTO 格式化成文字，
  `PortfolioWorkspace` 不参与 FX 盈亏计算——两处各算一套的风险已消掉。
- **临界汇率是 `T = (held.amount / cost_in_base) × tb.rate`**，即「历史成本价 × 当前 USD/CNY」，
  单位 JPY/USD = 配对自身的报价方向；旧 `breakeven_held_rate = th/tb` 是 JPY/CNY。两者都在结果里，
  端点与用例都断言「不同字段、不同数值」。
- **第三币种成本**：USD 批次的 `CostCurrency` 是 JPY（本段付出的货币），`UpstreamCosts` 回溯出 CNY
  （最初投入）。界面上两列并列，注释与说明都写「不要相加」。
- **口径统一**：`WorkspaceSnapshot.CumulativePnlBase = Σ 账户(总资产 − 净投入)`，任一账户未知则整体
  `null`（界面「未知」）。`valuation.TotalPnl`（未实现+已实现+分红）仍在快照里，但不再充当标题数字。

## 9. 待用户决定

1. **临界汇率的「无解」语义**（D5）：本模型是闭式求解，最多一个根，所以「无解」只可能来自缺输入
   （缺成本/缺报价/报价为 0），每种都给了原因。若用户想要的是「区间解」或「按概率的临界值」，
   那是另一个模型，需要另定。
2. **批次与账本余额的差额是否要自动建批次**：现在是「差额说清楚，不摊到批次上」。若用户希望
   「存入的外币也按当日汇率折算成成本」，那是新语义（会把未知变成推算值），需要拍板。
3. **提醒的 UNKNOWN 是否要单独通知用户**：现在 UNKNOWN 只写进报告的限制说明（不发送通知），避免
   每轮都因为行情抖动报警。若用户希望「连续 N 轮无法取价就发一条提醒」，需要定义阈值。
4. **FX 页面「现在换」的盈亏口径**：当前是「毛额」口径（`pnl_basis=gross`），成本模型（点差/固定费）
   另由路径卡承担。若希望标题数字就是「扣完成本」的净额，需要把成本输入设为必填。
5. **FX-03 要不要做、怎么豁免**（§7 第 6 条）：现在换出超过账户实有的钱会被接受并留下负现金。
   若要做成「现金/银行账户拒绝超额换出」，需要先定：融资账户怎么豁免、未建账的外币怎么期初化
   （审查报告建议 `OpeningLot`）、以及本包 A1–A4 这类「没有先入金」的夹具要不要改写。

- 不做购汇额度、保险账户、Android、指数对比曲线、完整 Lot 分配策略库（任务书明确排除）。
- 提醒的 UNKNOWN 状态不额外通知（见 §9 第 3 条）。
- `fx_paths` 的 5 条路径仍是既有的五条（已持有/新资金/绕行/持有/分批），没有做通用路径枚举。
- 界面只在汇率页；首页/总览不展示批次。
