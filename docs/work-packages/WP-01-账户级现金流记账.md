## 背景

用户不按每笔股票买卖记账，也不想记。他要的是账户级现金流：**投入、转出、转到自己的另一个账户、以及"这个账户今天值多少钱"**，由此算出收益。参考形态见有知有行账本（用户提供截图，不在仓库内）。

现有软件要求按交易记账，换汇要填 8 个框，用户评价"很不顺手"。股票买卖路径**保留**，但不再是主路径。

收益率算法已经存在且正好匹配：`ReturnMetrics.Xirr(externalFlows, finalValue, asOf)`。

## 目标（用户能得到什么）

1. 记一笔只需 **日期 + 操作 + 金额(+对方金额) + 备注**，不超过 4 个输入。
2. 四种操作：**投入 / 转出 / 转到我的另一个账户 / 当天资产金额**；换汇是"转到另一个账户"的跨币种形态，两边都抄回单，不填汇率。
3. 每个账户显示：总资产、累计收益、资金加权收益率、年化。
4. 多币种下这些数**依然算得出来**；算不出时明确说"未知"，不静默消失。

## 统筹已查清的下游规则（不要凭印象推翻，发现不符先报告）

这些是写代码前必须遵守的既有约束，均已核到代码行：

**R1 `当天资产金额` 不是现金流水，不能走 `AddCash`。**
它是对账户市值的断言（含未记录持仓的浮盈）。若按 `Deposit` 处理，净投入和 XIRR 全部失真。
依据：`PositionCalculator.cs:79-85`、`ValuationEngine` 以 `TotalValue = CashValue + Σ持仓市值` 合成。

**R2 账户必须有明确的估值模式，不能混。**
断言估值的账户**不得再**用"现金+持仓"算一遍市值，否则重复计数。每个账户二选一：`明细`（记交易，算市值）或 `余额`（报总额）。同一账户同时存在两者时必须拒绝或明确优先级，不能默认叠加。

**R3 账户间转移在账户层是外部流，在组合层是内部流。**
`LedgerTransaction.IsExternalFlow` 现在是 `Deposit | Withdraw | OpeningCash | OpeningPosition`（`LedgerTransaction.cs:99`），驱动 XIRR。用"A 出金 + B 入金"表示转移会让组合 XIRR 看到一进一出的假外部流，且两条记录互不关联。新 `Transfer` 必须成对、可追溯，并在组合层**排除**出外部流。

**R4 `FxExchange` 当前不算外部流，这是对的**，不要改。钱没离开组合，只换了币种。

**R5（硬伤，必须解决）多币种会让收益率直接消失。**
`PortfolioWorkspace.TryXirr` 在任一外部流币种 ≠ 本位币时 **直接返回 null**（`PortfolioWorkspace.cs:274-280`）。用户第一次记一笔日元投入，收益率就没了——而多币种正是本项目的核心场景。
要求：外部流按**该流发生当日**的汇率折算到本位币（不是今天的汇率）。缺当日历史汇率时，结果标为**不完整/未知并说明缺哪天**，不得用今天汇率补、不得静默返回 null。历史汇率表 `fx_rates` 主键为 `(base, quote, as_of)`，`as_of` 只有日期。

**R6 迁移方式。**
`PortfolioStore` 用 `if (current < N) { ... }` 顺序迁移，末尾写 `PRAGMA user_version`。本包新增 v10，须沿用该形式，并保留既有的迁移前 `.bak` 备份行为。

**R7 冲正必须覆盖新类型。**
新增类型要能被 `Reversal` 冲正，`PositionCalculator.Replay` 要跳过冲正对。物理删除仍然禁止。

## 步骤

1. **先写验收向量，再写实现。** 把本文「验收标准」里的算例落成测试，先红后绿。
2. 领域：新增 `TransactionKind.BalanceAssertion` 与 `TransactionKind.Transfer`；按 R1/R3/R4 定义它们在 `Replay`、`IsExternalFlow`、估值中的行为。
3. 账户：加估值模式字段（R2），默认 `明细` 以兼容现有账本；新建账户时可选 `余额`。
4. schema v10（R6）：新类型落库、账户模式列、必要索引；迁移幂等，重复执行无副作用。
5. 收益率：按 R5 实现多币种外部流折算与「不完整」状态；`TryXirr` 不再静默 null。
6. 界面：新「新增记录」对话框，4 种操作，字段随操作显隐；换汇两边金额并排，汇率只读显示。旧「记一笔」保留可达，不删。
7. 列表：账户页显示更新记录（日期/操作/金额）与四个汇总数（总资产、累计收益、资金加权收益率、年化）。
8. 冲正与 CSV（R7）：新类型可冲正、可导出；CSV 导入本包**不要求**支持新类型，但不得因新类型而崩。

## 验收标准

每条都要有断言测试，不接受"手工看过"。

| # | 场景 | 必须成立 |
| --- | --- | --- |
| A1 | 账户 2022-09-13 期初 0，陆续投入合计 180,000.00，转出合计 −12,000.00，最后报当天资产金额 195,000.00 | 净投入 = 168,000.00；累计收益 = 27,000.00；期末 = 期初 + 净投入 + 盈亏 |

| A4 | 账户 A 转 10,000 到账户 B（同币种） | 两账户各自流水可见且成对关联；**组合层外部流不含这两笔**（R3）；组合总资产不变 |
| A5 | CNY 账户转出 50,000 → JPY 账户转入 1,052,673（跨币种=换汇） | 不需填汇率；派生成交比率可显示；组合层不计为外部流（R4） |

## 风险

- **R2 的模式选择是本包最容易出错的地方。** 余额模式与明细模式混用会静默重复计数，且不会报错。优先为它写测试。
- **R5 需要历史汇率，可能大面积缺数据。** 先确认 `fx_rates` 实际有多少历史覆盖；缺得多就如实暴露为「不完整」，不要为了让数字好看去补算。
- 新增两个流水类型会触及 `Replay`、估值、冲正、导出、CSV 五处分支，**漏一处就是静默错账**。改 `TransactionKind` 后把所有 `switch` 全找一遍。
- UI 改动必须真正启动应用验证（BAML 运行时才加载），`dotnet build` 通过不代表界面能开。
